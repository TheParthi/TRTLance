## A. Project Risk Analysis

**Purpose.** Before bidding, a freelancer sees an objective assessment of the project's risk: vague scope, unrealistic timeline, budget problems, missing milestones and likelihood of disputes.

**Trigger.** A signed-in user who is not the project owner clicks **Apply to this Job** on `/job/[jobId]`. The modal posts `{ projectId }` to `/api/ai/project-risk`; "Proceed Anyway" then opens the bid form. The report can be reopened later.

**Pipeline.**

1. `POST /api/ai/project-risk` authenticates the user and loads the project.
2. **Cache:** if `ai_project_risk_reports` has a row for (project, user), return it.
3. Map project fields to the model input: `title`, `description`, `budget` (from `budget_min`), `duration` and `milestones` — the last one reads a column that does not exist, so the model is always told "None".
4. Run the Genkit flow `projectRiskAnalysisFlow` (`src/ai/flows/project-risk-analysis.ts`) with the model `googleai/gemini-2.0-flash` (`src/ai/genkit.ts`).
5. Save the result and return it.

**Prompt (summary).** "You are an AI assistant analysing freelance projects for potential risk, objectively and neutrally." It lists the five checks above, inserts the project fields, and demands "ONLY valid JSON" in a fixed shape, with no advice, legal terms or extra text.

**Schemas.**

```
input:  { title: string, description: string, budget: string|number,
          duration: string, milestones?: string }
output: { risk_level: "LOW" | "MEDIUM" | "HIGH",
          risk_summary: string, issues: string[], confidence_score: number }
```

**Presentation.** `RiskAnalysisModal` shows a colour-coded risk level, the issue list and a confidence bar, plus a disclaimer. A PDF of the report (jsPDF) **downloads automatically** every time the modal opens.

**Cost and latency.** One Gemini Flash call per (project, freelancer) pair, a few hundred tokens each way — a small fraction of a cent per report, a few seconds of latency on the request path, with no timeout, retry or rate limit.

<div class="callout risk"><span class="callout-title">Problems to fix before relying on it</span>
<b>Fake reports.</b> Any error (missing key, quota, schema mismatch) produces a hard-coded "LOW risk, 85 % confidence" report that is <b>saved as if real</b> and then served from cache forever for that user.<br>
<b>Forgeable cache.</b> The table's insert policy is <code>WITH CHECK (true)</code>, so anyone can insert a report for another user; with no unique key, duplicates also break the cache lookup and trigger repeated model calls.<br>
<b>Prompt injection.</b> The client writes the description that goes straight into the prompt and could steer the verdict.<br>
<b>Missing context.</b> Milestones, skills, category, experience level and currency are not passed to the model.</div>

## B. AI project recommendations (unused)

`src/ai/flows/ai-project-recommendations.ts` is the Firebase Studio template flow: given a free-text user profile it asks Gemini for N recommended projects or freelancers with a match score from 0 to 1. It has no database grounding — the model would invent ids and names — and no caller.

## C. LangChain dispute agent (unused)

`backend/ai/dispute-agent.js` (227 lines) was designed to recommend dispute outcomes:

- **Provider** chosen by `AI_PROVIDER`: `openai` (`MODEL_NAME`, default gpt-3.5-turbo), `ollama` (llama3:8b at `OLLAMA_BASE_URL`, the default) or `mock`.
- **Data:** reads the dispute, the project with its milestones, messages and evidence using the service-role key.
- **Output** (zod schema): `outcome` FREELANCER / CLIENT / PARTIAL, `freelancer_percentage`, `confidence_score`, `reasoning`, `key_factors`, `evidence_summary` — exactly the inputs of `ProjectEscrow.resolveDispute`.
- **Mock mode** decides from the share of approved milestones (> 80 % → freelancer, < 30 % → client, otherwise partial).
- **Gaps:** the gathered messages and evidence never reach the prompt, it reads the unused `milestones` table, it does not load environment variables, and nothing — no route, script or import — runs it. Its dependencies live only in `backend/node_modules`, so the Next.js app cannot import it as-is.

## D–H. Simulated AI

These are UI demonstrations without models: keyword-matched chat replies, `Math.random` risk scores, hard-coded verdicts on two sample disputes (DSP-001 and DSP-002), constant admin metrics and static bid insights. They should either be connected to real logic or clearly labelled as demos.

## Recommended AI roadmap

1. Make the risk report trustworthy: never persist fallbacks, add a unique key and server-only inserts, pass the real milestones and skills, and wrap the description as untrusted data in the prompt.
2. Cache per project (not per user) so N applicants cost one model call.
3. Turn the dispute agent into a server-side Genkit flow that reads the contract, submissions, chat and evidence, and produces a recommendation the arbitrator sees — never an automatic decision.
4. Replace the simulated screens with the real outputs, or remove them.
